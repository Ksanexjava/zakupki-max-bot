# Бот закупок для MAX + панель заявок

Работник оформляет заявку в боте MAX → вам прилетает уведомление в MAX →
вы ведёте заявку в веб-панели и меняете статусы → работнику автоматически
приходит сообщение о смене статуса.

```
Работник в MAX  ──►  бот (6 вопросов)  ──►  SQLite  ──►  HTML-панель
                            │                               │
                            └──── уведомление вам в MAX ◄────┘
                                  уведомление автору о статусе
```

Стек: [maxapi](https://github.com/love-apples/maxapi) (роутеры, FSM, long polling),
SQLAlchemy 2 (async), aiohttp для панели. Python 3.10+, проверено на 3.12.

## Что собирает бот

| Поле | Обязательное | Как заполняется |
|---|---|---|
| Кто заказывает | да | кнопка «Это я» или «Это не я» → вписать ФИО коллеги |
| Что заказывает | да | текстом |
| Сколько | да | текстом |
| К какому сроку | да | кнопкой или текстом |
| Зачем (цель) | да | текстом |
| Пример: ссылка или фото | нет | ссылкой, фото или кнопкой «Пропустить» |

## Статусы

| Статус | Когда ставится |
|---|---|
| 🆕 Не просмотрено | автоматически при создании заявки |
| ⚙️ В работе | вручную в панели или кнопкой в MAX |
| ❓ На уточнении | вручную; обычно вместе с комментарием автору |
| ✅ Заказано | вручную |
| 🏁 Выполнено | вручную — закупка закрыта, товар у заказчика |

Заявку можно удалить — кнопка внизу карточки в панели, с подтверждением.
Удаляется вместе с историей и фотографией, автору уходит сообщение.

Добавить свой статус (например «Отклонено») — одна строка в `STATUSES`
в [core/statuses.py](core/statuses.py) и один цвет в [static/styles.css](static/styles.css).

## Быстрый старт

### 1. Бот в MAX

В MAX откройте **@MasterBot** → `/newbot` → задайте имя и адрес → скопируйте токен.

### 2. Настройки

```bash
cp .env.example .env
```

Заполните в `.env`:

- `MAX_BOT_TOKEN` — токен от @MasterBot;
- `PANEL_USERS` — логины и пароли панели: `PANEL_USERS="mike:пароль1,ivan:пароль2"`;
- `SECRET_KEY` — `python3 -c "import secrets; print(secrets.token_hex(32))"`;
- `ADMIN_CODE` — секретное слово, чтобы подписаться на уведомления;
- `DISPLAY_TZ_OFFSET` — часовой пояс для дат (3 — Москва, 7 — Красноярск).

### 3. Запуск

```bash
./run.sh
```

Скрипт создаст venv, поставит зависимости и запустит бота вместе с панелью
на http://127.0.0.1:8080. Если окружение уже готово — то же самое делает:

```bash
python -m bot.main
```

### 4. Подписка на уведомления

Напишите своему боту в MAX:

```
/admin ВАШ_ADMIN_CODE
```

Бот ответит «теперь вы получаете уведомления». Так же может подписаться
второй человек — уведомления придут обоим.

## Как пользоваться

**Работник:** открывает бота → «Создать заявку» → отвечает на вопросы →
смотрит статусы своих заявок командой `/my`. Бот пишет ему сам, когда:

- меняется статус заявки (было → стало, вместе с комментарием);
- закупки отправили комментарий без смены статуса;
- заявку удалили.

Всё это отключается одной строкой `NOTIFY_AUTHOR=false` в `.env`.

**Вы:** открываете панель — заявки идут таблицей. Клик по строке открывает
карточку, в ней можно:

- приложить скриншоты заказа: перетащить файл, вставить из буфера (`Cmd+V`)
  или выбрать на диске. PNG, JPEG, WebP, GIF до 10 МБ, видны только в панели;
- написать комментарий автору;
- поставить статус (комментарий уйдёт автору вместе с ним);
- удалить заявку.

Быстро сменить статус можно и прямо из уведомления в MAX, кнопками под сообщением.
Ссылка из уведомления открывает нужную карточку сразу.

Тема оформления — переключатель в шапке: светлая или тёмная. Выбор запоминается
в браузере; пока его не трогали, панель следует настройке системы.

Команды: `/new`, `/my`, `/cancel`, `/help`, `/id` (узнать свой user_id),
`/admin <код>`, `/unadmin`.

## Структура

```
config.py            настройки из .env (dataclass Settings)
bot/
  main.py            точка входа: Dispatcher + long polling + запуск панели
  handlers/
    start.py         /start, /help, /cancel, /my, главное меню
    request.py       пошаговая форма заявки
    admin.py         /admin, /id, кнопки смены статуса под уведомлением
    fallback.py      всё остальное (подключается последним)
  states.py          шаги анкеты (StatesGroup)
  keyboards.py       инлайн-клавиатуры и payload кнопок
  texts.py           все тексты бота
  media.py           сохранение фото из заявки
core/
  statuses.py        справочник статусов
  notifications.py   уведомления админам и авторам (нужны и боту, и панели)
db/
  models.py          таблицы: requests, status_history, admins
  repo.py            весь доступ к данным
  session.py         движок SQLAlchemy и create_all
panel/
  server.py          HTTP-панель: авторизация, список, статусы, комментарии
static/              index.html, app.js, styles.css
tools/
  seed_demo.py       демо-заявки для панели
  dry_run.py         прогон диалога без сети
  fakes.py           заглушки MAX для тестов и прогона
tests/               pytest: репозиторий, диалог, маршрутизация, панель
deploy/              systemd-сервис и пример конфига nginx
data/                purchases.db и media/ (в git не попадает)
```

Где хранятся шаги незаполненной заявки: в памяти процесса, а если задан
`REDIS_URL` — в Redis (тогда они переживают перезапуск). Сами заявки всегда в базе.

## Второй экземпляр для другого человека или отдела

Код не привязан к конкретному боту — всё в `.env`. Чтобы запустить отдельную
копию (другая компания, другой отдел, тестовый контур):

1. Создать **своего** бота у @MasterBot и получить токен.
2. Скопировать проект **без** `.env` и папки `data/`.
3. `cp .env.example .env` и заполнить свои `MAX_BOT_TOKEN`, `PANEL_USERS`,
   `SECRET_KEY`, `ADMIN_CODE`.
4. `./run.sh`, затем в MAX боту — `/admin <свой код>`.

Чего нельзя делать:

| Нельзя | Почему |
|---|---|
| Два процесса с **одним** токеном | Long polling раздаёт каждое событие только одному получателю — половина заявок будет теряться |
| Общая `data/purchases.db` у двух экземпляров | Пересекутся номера заявок и получатели уведомлений |
| Один `PANEL_PORT` на одной машине | Второй процесс не стартует: «address already in use» |

Для двух копий на одной машине достаточно развести `PANEL_PORT`, `DATABASE_URL`
и `MEDIA_DIR` — остальное они не делят.

## Проверка без подключения к MAX

Панель на тестовых данных:

```bash
python -m tools.seed_demo     # 5 демо-заявок
python -m bot.main            # без токена поднимется только панель
```

Весь диалог бота в консоли (без токена и без сети):

```bash
python -m tools.dry_run
```

Тесты:

```bash
python -m pytest tests -q
```

Удалить тестовые данные: `rm data/purchases.db`

## Если бот не подключается

| Симптом | Что делать |
|---|---|
| `401` / `verify.token` | Проверьте `MAX_BOT_TOKEN` |
| Не достучаться до API | Задайте `MAX_API_BASE` (например `https://platform-api.max.ru`) — MAX переезжал между доменами |
| `certificate verify failed` | Поставьте на сервер корневой сертификат Минцифры |
| Бот не видит сообщения | У бота не должно быть активной webhook-подписки: long polling и webhook несовместимы |
| Уведомления не приходят | Отправьте боту `/admin <ADMIN_CODE>` или впишите свой `user_id` в `ADMIN_USER_IDS` (узнать: `/id`) |

Деплой на сервер — [DEPLOY.md](DEPLOY.md).
